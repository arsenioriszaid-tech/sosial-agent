# Decision: Content Contract V0.1 (canonical draft)

Date: 2026-09-20. Status: implemented on branch v0.1/content-contract.

## Evidence (real run 2026-09-20, contract V0)

1. 4/4 research items became drafts — nothing could SKIP (vendor-claim
   items r2/r4 indistinguishable from solid ones at the gate level).
2. All 4 drafts exactly 280/280 chars with mid-sentence cuts
   ("infrastruktu…", "estima…", "memangkas…", "di e…").
3. The template forced every topic into a question/hook ("Open question: …"),
   converting substantive topics into engagement formats.

## Decision

Revise to V0.1 with pipeline
research → verified facts → context → analysis → core observation
→ canonical draft → human review → platform adaptation.

- Canonical draft: complete thought (what + why relevant), 1–3 paragraphs,
  target 400–800 chars (config/canonical.yaml), no hard limit.
- Facts/Analysis/Take labeled apart; take optional; question only if the
  operator's analysis contains one (validator proves the template adds none).
- New SKIP gates: headline-only depth, thin context (<40 chars), unverified
  main claim, bait-without-substance. Legacy V0 input fields still parse via
  documented fallback mapping.
- Platform budgets constrain only the adaptation note (FITS / NEEDS_REVIEW);
  the engine never truncates canonical text.
- Recruitment Engine untouched. No dashboard/database/network/live research.
  Traceability, safety scan, uncertainty handling, human-review boundary kept.

## Verification

- Same 4 items rerun under V0.1: 4 canonical drafts (593/835/694/728 chars),
  validator 30/30 (1 length WARN, valid by design).
- Fixtures (6 items): 2 drafts + 4 skips, each SKIP reason as designed.
- Legacy V0-schema inputs: still run (3 drafts + 1 skip).
- Flipping one real item to claim_trust=unverified: correctly SKIPped.
