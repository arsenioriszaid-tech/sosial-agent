# Content Drafting (V0.1 canonical contract)

Goal: turn research into a specific, informative, relevant observation with a
builder/operator angle. Engagement is not the objective.

Pipeline: research → verified facts → context → analysis → core observation
→ canonical draft → human review → platform adaptation.

Canonical draft rules:
- A complete thought: what happened and why it is relevant (1–3 paragraphs,
  target 400–800 chars, no hard limit).
- May contain an interpretation/take, but facts and interpretation must be
  labeled apart (Facts / Analysis / Take).
- No mandatory hook, question, CTA, or engagement bait. A question appears
  only if it is a substantive part of the analysis.
- Never invent user experience, opinions, or facts. Hedged where uncertain.

SKIP when: headline repetition only, no meaningful observation, context too
thin, main claim not trustworthy enough, or the draft is only interesting
as controversy/engagement bait.

Platform adaptation is separate: platform character budgets never constrain
the canonical draft. Never truncate mid-sentence; if a draft cannot be
reasonably condensed, mark NEEDS_REVIEW for a human to adapt.

Return: canonical draft, core observation, evidence basis (facts),
interpretation (take or explicit no-take), uncertainty, platform notes.
